# 艾西語音部署前巡檢契約

艾西的語音服務不應以「再裝一套」為預設。部署前須先在 **N1 桌機** 執行唯讀巡檢，盤點既有語音執行環境、半完成安裝與受管理程序，再依結果選擇沿用、補完、升級或建立新服務。

| 巡檢範圍 | 取得內容 | 刻意不讀取的內容 |
|---|---|---|
| 執行環境 | Python、Node、PM2、Docker、Ollama、FFmpeg、GPU 指令是否可用 | Shell 歷史、環境變數值、登入資訊 |
| 語音工具 | 已安裝的已知 TTS／轉寫套件「名稱與版本」 | 套件設定內容、使用者資料 |
| 服務程序 | 符合語音關鍵字的 PM2、Docker、systemd 名稱與狀態 | PM2／Docker 環境變數、容器內檔案 |
| 檔案跡象 | N1 腦目錄中語音相關檔名與資料夾路徑 | `.env`、金鑰、任意設定檔與音訊內容 |
| 模型清單 | 已安裝 Ollama 模型的名稱與大小 | 模型權重、提示詞、記憶資料 |

> 巡檢輸出只是一份部署決策輸入，**不是**部署證明，也不會啟動 TTS、生成語音、重啟 PM2、安裝套件或改寫設定。

## 決策規則

| 巡檢結論 | 功能效果 | 下一步 |
|---|---|---|
| `REVIEW_EXISTING` | 已偵測到已知語音執行套件 | 先確認既有服務的 API、模型、GPU 佔用與輸出品質；避免第二套競爭資源。 |
| `REVIEW_OR_COMPLETE` | 偵測到語音目錄或檔名，但未能確認受支援執行環境 | 先核對未完成安裝來源，再選擇補完或清理；不直接覆蓋。 |
| `CLEAN_INSTALL_CANDIDATE` | 未偵測到常見本機語音堆疊 | 可選定雲端或本機 TTS，產生個別部署計畫與可回復安裝器。 |

## 與 App 的邊界

手機 App 只顯示巡檢結論、服務健康度與由 N1 回傳的音檔 URL。App 不保留 SSH 私鑰、Git／R2／TTS API 金鑰，也不直接部署服務。任何外部 TTS 金鑰都必須保留在 N1 的受控服務端。
