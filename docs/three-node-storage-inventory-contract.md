# 三機唯讀儲存盤點契約

本契約讓 ELSA 取得 **N1、N2、N3 各自明確產生的儲存快照**，以便在記憶中心分析每台設備的磁碟、掛載點、可用容量與可供使用者選取的匯入來源。它不會把「SSH 埠可連」誤寫成「已讀取儲存資料」；每個節點都必須完成自己的唯讀盤點並回傳帶時間戳的報告。

| 層級 | 允許的資訊 | 明確不收集的資訊 |
| --- | --- | --- |
| 網路可達性 | 主機代號、探測結果、探測時間 | 不把 TCP 可達性當成登入或磁碟存取成功 |
| 節點盤點 | 作業系統摘要、主機名稱、掛載點、檔案系統類型、容量與使用量 | 檔案內容、目錄遞迴清單、檔名、Shell 歷史、憑證或 Token |
| 匯入來源 | 使用者目錄、Downloads、Android shared storage、Termux、Nix 等「是否存在」的錨點 | 自動掃描 Root、Vault、App manager 或其他受保護 App 資料 |
| N1 彙整 | 固定三機報告、報告狀態、最後盤點時間 | 手機端 SSH 私鑰、雲端帳密、原始遠端錯誤內容 |

> **報告狀態的意義**：`reported` 表示節點已成功執行盤點並產生有效 JSON；`stale` 表示最後成功報告逾 24 小時；`probe_failed` 表示 N1 的唯讀探測未成功；`unreported` 表示尚未產生任何可驗證報告。它們都不等同於「設備不存在」。

## N1 端點

| 路由 | 權限 | 用途 |
| --- | --- | --- |
| `GET /api/system/storage-inventory` | 唯讀 | 讀取 N1 已保存的三機報告摘要與各節點容量資料 |
| `GET /api/system/storage-inventory/N1` | 唯讀 | 讀取單一節點的已保存報告；節點限於 `N1`、`N2`、`N3` |

掃描本身不是公開 API。安裝器會把 `elsa_storage_inventory_probe.sh` 放在 N1 的本機工作區；只有在 N1 終端執行該檔案時，它才會透過固定 SSH 目標執行**不寫入遠端、不讀取檔案內容**的節點盤點。行動 App 只讀取報告，不能自行啟動跨機掃描。

## 資料流與分析規則

每次盤點先在節點以目前登入使用者的權限執行，N1 再把每個節點的 JSON 存放在 `.elsa_perpetual/storage_inventory/`。分析只以成功回傳的 volume 資料計算每台設備的容量壓力：使用率達 85% 以上視為需要注意，未回報節點不納入加總。N1 的記憶索引與 R2 原始封存仍是不同層級；盤點只提供容量與來源可見性，不宣告任何文件已被索引或已上傳。

## 操作選項

| 方式 | 適用情境 | 取捨 | 設定難度 |
| --- | --- | --- | --- |
| 手動按需盤點 | 先建立可信的三機清單、需要時才刷新 | 不會有背景存取；需在 N1 終端主動執行一次 | 低 |
| N1 定時唯讀盤點 | 希望每天更新容量趨勢 | 需要另行設定本機排程與失敗告警；仍只收集 metadata | 中 |

目前交付第一種方式。若要加入定時盤點，將以 N1 本機的確定性任務執行，並先新增心跳、失敗重試、過期告警與停用開關，避免把裝置盤點變成失控的背景掃描。
