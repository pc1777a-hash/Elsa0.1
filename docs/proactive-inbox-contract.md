# 永動腦主動收件匣與視覺狀態卡契約

## 目的

本契約讓 N1 永動腦可以向 ELSA App 提交**系統報告**、**對話邀請**與**視覺狀態卡**。它不是聊天紀錄鏡像，也不把模型回覆、任務名稱或 TCP 可達性誤當成艾西已主動執行。

| 項目 | 契約規則 |
|---|---|
| 讀取路由 | `GET /api/perpetual/events` |
| 外層來源 | 固定為 `n1-proactive-events/1` |
| 事件上限 | 最多 80 則，由 N1 依時間倒序輸出 |
| 必填證據 | 事件 ID、來源、時間、觸發原因、標題、內容、嚴重度與驗證狀態 |
| 容許類型 | `system_report`、`chat_invite`、`status_card` |
| 驗證狀態 | `reported` 或 `verified`；缺失即由 App 拒絕 |
| 視覺卡 | 僅能作為視覺化狀態，必須有 `is_visualization: true`，不表示任務已完成 |

## 安全與真實性邊界

事件檔只能由 N1 永動腦或受控工作者寫入。App 採前景輪詢讀取，沒有事件時顯示「未回報」，不從 `/ask`、交易結果、SSH 埠狀態或自我推論產生假事件。心情、焦點與意圖仍以 `/api/ai/self-status` 的明確自我回報為唯一來源。

| 類型 | 合格範例 | 不合格範例 |
|---|---|---|
| 系統報告 | N2 儲存盤點已過期，附報告 ID | 「我覺得系統沒問題」 |
| 對話邀請 | 有來源與觸發條件的工作者邀請 | 從一般聊天回覆抽取一句話 |
| 狀態卡 | 任務狀態與自我回報的視覺化 | 將角色圖當成任務完成證據 |

## 主人通知偏好

第一版只在 App 前景同步時顯示收件匣。推播、背景排程或自動發送前，須另訂通知偏好與 N1 事件遞送契約；它們不能以行動 App 前景存活作為工作者持續運作的依據。

## 非重複動態角色圖

主動事件可選擇附上一張新的狀態圖，但圖像只有在 N1 同時具備**明確自我回報**與**具體工作事件**時才可生成。N1 必須使用固定的角色參考版本維持艾西的臉部、髮型、輪廓與核心配色，並以心情、焦點、近期意圖及工作內容改變表情、姿勢、服裝細節、道具與背景。每次輸出需附帶下列可稽核欄位。

| 欄位 | 規則 |
|---|---|
| `image_url` | 僅接受 HTTPS 圖像 URL；App 將其當成視覺素材而非執行證據。 |
| `character_reference_version` | 必填於有新圖的事件，指出固定角色參考素材或版本。 |
| `prompt_digest` | 不含秘密值的提示摘要，記錄心情、場景和工作元素如何映射。 |
| `generated_at` | 影像生成完成時間。 |
| `is_visualization` | 固定為 `true`；未標示即被 App 拒絕。 |

沒有明確自我回報、工作事件、角色參考版本或 HTTPS 圖片來源時，App 必須維持「未回報」或既有角色佔位視覺，不可自行編造新的艾西心情圖。
